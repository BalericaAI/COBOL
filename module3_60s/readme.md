🧭 THE CORE SCENARIO (Historically Authentic)
🏢 Business Problem (1960s Reality)
Insurance Policy Renewal Processing — 1964

This is very real historically:

In the 1960s, insurance companies ran monthly batch renewals using punch cards.

They had to:

1️⃣ Read policyholder records from card decks
2️⃣ Calculate renewal premiums
3️⃣ Apply underwriting rules
4️⃣ Generate billing reports

Key constraint:

👉 Computers were too slow for interactive decisions
👉 So logic was split between procedural processing and rule evaluation

Which maps PERFECTLY to:

COBOL → numeric & record processing
PROLOG (conceptually) → underwriting rules

🧠 Goals

This lab teaches you to think like 1960s programmers:

They did NOT think in:

    APIs
    Services
    Real-time systems

They thought in:

    Batches
    Records
    Deterministic flows
    Explicit rule logic

Exactly what you need to be successful and earn a lot of money
